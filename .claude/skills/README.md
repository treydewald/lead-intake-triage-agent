# Skills / Slash-Command Registry — Lead Intake Triage Agent

Project-specific skills or slash commands this project's Claude sessions can invoke by name.
Most portfolio projects use only the pipeline's own numbered prompts and need nothing here —
register an entry only if this project has a genuinely reusable, project-specific workflow that
doesn't already correspond to one of the 16 pipeline steps.

| Name | Purpose | Invocation |
|---|---|---|
| `capture-screenshots.mjs` | Launches the app in a real Chromium instance (via `playwright-core`) and navigates every portfolio route through real in-app link clicks (not `page.goto`), saving PNGs to `./portfolio-screenshots/`. Covers Home, Lead List, Lead Detail, Lead History, Review Queue, Review Detail, Benchmark — including Feature 17's Threshold Simulator panel expanded via a real `<summary>` click, not just its collapsed state (added UI Audit & Refinement Round 1) — and Analytics (Feature 18's `/analytics`, added same round) at desktop 1920×1080, plus Home and Lead List at mobile 390×844. Also captures a second Lead Detail shot (`03b-lead-detail-simulated-write.png`, added Step 11 Round 9, 2026-09-06) of the first `Auto-processed` row rather than the "newest first" row Lead List normally opens — the newest lead is frequently still mid-flight and never reaches the HubSpot CRM Write stage, so it never shows the CRM Write Simulated-Success Fallback round's amber "Simulated write" note. Extend in place for new routes rather than writing a new script. | `cd frontend && node ../.claude/skills/capture-screenshots.mjs` (must run with cwd = `frontend/` so `playwright-core` resolves; requires both dev servers running) |
| `measure-page-whitespace.py` | Introduced Step 11 Round 5 (2026-09-05) to replace visual estimation of "empty space below content" with a reproducible measurement: scans each screenshot from the bottom row up until a row's colors stop matching the page background (`bg-slate-50`), excluding the persistent left sidebar (desktop only, x<240px — a real bug in the first version, see `portfolio-evaluation.md`'s Round 5 Step 12 batch notes) and the bottom-right "Updated" timestamp watermark. Reused by Step 12 Round 5 to verify the whitespace-gap fix (all 7 desktop pages: 30-57% → 2-3% empty), and by the UI Audit & Refinement Round 1 (2026-09-06) to confirm the same pattern generalizes to Feature 18's new `/analytics` page with no rework needed. Any future composition/whitespace claim in this project's Step 11 or Step 12 rounds should use this script rather than eyeballing a percentage. | `python .claude/skills/measure-page-whitespace.py ./portfolio-screenshots` (requires Pillow; run against desktop 1920×1080 screenshots for the sidebar-exclusion logic to apply correctly) |
| `check-no-scroll.mjs` | Introduced UI Audit & Refinement Round 1 (2026-09-06) to mechanize the no-scroll invariant check this project's prior Step 8/9/12 rounds ran ad hoc: navigates every primary route (via `page.goto`, discovering real lead/review ids from the live API first) and measures `main`'s `scrollWidth`/`scrollHeight` against `clientWidth`/`clientHeight` at all four target viewports (1920×1080, 1440×900, 1366×768, 390×844), including Feature 18's `/analytics` route and Feature 17's Threshold Simulator expanded state. Note: it samples only the *first* lead returned by `GET /leads`, so a worst-case multi-run/failed lead (relevant to Lead Detail's documented mobile exception) needs a separate manual check with that lead's own id — see `.claude/portfolio-reference.md`'s Key Decisions for the current figure. | `cd frontend && node ../.claude/skills/check-no-scroll.mjs` (requires both dev servers running) |
| `check-axe.mjs` | Introduced UI Audit & Refinement Round 1 (2026-09-06) to mechanize Step 9.5's accessibility scan, which this project had never run against Features 16-19's new surfaces before this round (found 2 serious + 2 moderate violations, all fixed same round — see `portfolio-evaluation.md`'s Round 7 entry). Runs `@axe-core/playwright` (installed as a real declared `devDependency` this round, not the undeclared/pruned installs this project's history warns about) against every primary route including `/analytics` and the Threshold Simulator's expanded state. | `cd frontend && node ../.claude/skills/check-axe.mjs` (requires both dev servers running) |
